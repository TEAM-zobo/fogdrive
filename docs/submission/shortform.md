# 숏폼 (선택) — 캐릭터 숏폼 제작 가이드

접수양식 02-8에 링크를 적는 세로 영상입니다. 본상 가산점은 없고, 별도 특별상(1팀, 50만 원, 2027년 2월 행사 초청)이 있습니다.

이 문서는 **다른 컴퓨터에서 Claude Code에게 이 파일만 주고 숏폼을 만들게 하는 가이드**입니다. 애니메이션 캐릭터(아빠·아이·가족)가 나와서 부릉탐험대 앱 서비스를 소개하는 트렌디한 세로 숏폼을 만듭니다. 내용의 근거는 기획서(접수양식)입니다.

## 다른 컴퓨터에서 시작하기

1. 저장소를 받고 `main` 브랜치로 맞춥니다.
2. 영상 도구를 설치합니다: macOS `tools/setup/setup.sh video`, Windows `powershell -ExecutionPolicy Bypass -File tools\setup\setup.ps1 video` (ffmpeg, Node.js 22+, HyperFrames 스킬). 설치 후 Claude Code를 다시 엽니다.
3. Claude Code에 아래 프롬프트를 그대로 붙여 넣습니다.

```text
docs/submission/shortform.md 가이드대로 부릉탐험대 캐릭터 숏폼을 만들어 줘.
기획서는 docs/submission/02-app-introduction.md(= docs/submission/application-form.docx의 02 내용)를 참고하고,
앱 화면은 docs/images/burung/ 이미지를 써 줘. /hyperframes 스킬로 tools/demo/burung-toon/ 에 프로젝트를 만들고,
장면마다 snapshot으로 프레임을 직접 확인한 뒤 render해 줘.
```

## 만들 영상

- **형식:** 세로 9:16, 1080×1920, 30fps, **30–45초**(공모전 기준 30초–1분)
- **프로젝트 위치:** `tools/demo/burung-toon/` (HyperFrames). 편집은 `build.py`만 고치고 `index.html`·`compositions/`는 생성물로 둡니다
- **결과물:** `tools/demo/burung-toon/renders/burung-toon.mp4` (git 제외: `renders/`, `node_modules/`, `.hyperframes/`)
- **분위기:** 밝고 귀여운 2D 애니메이션 캐릭터 + 실제 앱 화면. 릴스·쇼츠 문법(첫 1초 큰 글자 훅, 소리 없이도 읽히는 자막, 장면 3–5초, 밈 말투, 마지막 댓글 유도 질문)
- **기존 버전:** `tools/demo/burung-short`(40.6초)는 에뮬레이터 화면만으로 만든 버전입니다. 장면 흐름·자막 말투는 참고만 하고, 이 영상은 새 프로젝트로 만듭니다

### 등장인물

캐릭터 시트를 먼저 한 장 만들고, 모든 장면에서 같은 얼굴·옷·색을 유지합니다(장면마다 새로 그리면 사람이 바뀌어 보임).

| 캐릭터 | 설정 | 쓰는 장면 |
| --- | --- | --- |
| 아빠 A씨 | 40대 초반 직장인. 평일엔 아이 등원 후 출근, 주말엔 가족 나들이 | 전체 주인공 |
| 아이 (도현) | 유치원생. 차만 타면 지루해함 → 탐험대원으로 변신 | 키즈모드·도감 장면 |
| 엄마 | 주말 드라이브·여행 계획을 함께 함 | 주말·도감 장면 |
| 차 | 앱 아이콘의 빨간 작은 차(지붕에 노란 탐험 깃발) | 연결 장면, 엔딩 |

- 캐릭터 이미지는 HyperFrames `media-use` 스킬로 생성하거나(HeyGen 등) 직접 그린 일러스트를 씁니다. 사람 얼굴은 실존 인물과 닮지 않게 합니다
- 앱 화면은 그림으로 다시 그리지 않고 **실제 앱 캡처**를 차량 디스플레이·휴대폰 프레임 안에 넣어 보여 줍니다

### 기획서에서 가져올 핵심 메시지

장면 자막은 아래 문장에서 줄여 씁니다(출처: `02-app-introduction.md` 2·3·4번).

- 운전은 일상입니다. 대한민국 운전자는 하루 평균 30.8km를 달립니다(비상업용 자동차 기준, 한국교통안전공단 2025). 국내 여행 이동수단의 84.5%가 승용차입니다(2025 국민여행조사).
- 그러나 이 많은 주행은 내비게이션 안내가 끝나면 아무것도 남기지 않습니다. 동승한 가족, 특히 아이에게 차 안의 시간은 목적지까지 기다리는 시간일 뿐입니다.
- **운전이 ‘나만의 탐험 지도’가 됩니다.** 매일의 출퇴근이, 주말의 근교 드라이브가 도감으로 쌓여 내가 넓혀 온 세계를 한눈에 봅니다.
- **새로운 지역으로의 주행을 경험합니다.** 아직 가 보지 않은 동네와 이번 주 탐험을 제안하고, 목적지가 있으면 조금만 돌아가 안 가 본 동네를 지나는 길을 알려 줍니다. 누르면 바로 현대차 내비게이션 안내로 이어집니다.
- **함께 탄 가족도 탐험대원이 됩니다.** 함께 달린 날은 '오늘은 함께 탐험했어요!'로 남고, 우리 탐험대 이름으로 가족의 기록이 쌓입니다. 키즈모드는 처음 가 본 동네와 레벨 업 소식을 아이 눈높이 말투로 들려줍니다("짜잔! 처음 와 보는 ○○동이에요!").
- 앱 속 실제 칭호 이름: 「프로 출근러」(출퇴근), 「주말 원정대」(주말·여행), 「우리 동네 탐험가」, 「섬 탐험가」, 「서울 마스터」. 없는 칭호를 지어내지 않습니다(위 표의 칭호는 모두 실제 이름).

## 지켜야 할 것

- **글자 위치:** 자막·글자는 화면 위 **168–1330 px** 안에만 둡니다(그 아래는 릴스·쇼츠의 설명·버튼이 덮음)
- **안전:** 운전 중 화면을 만지거나 휴대폰을 보는 장면을 넣지 않습니다. 앱 조작은 정차(P단)·도착 후에만, 주행 중에는 지도만 보이는 앱 설계와 맞춥니다
- **개인정보:** 화면·파일 이름·계정에 성명·이메일·개인 계정 ID를 넣지 않습니다. 「도현 탐험대」가 실제 가족 이름이면 다른 이름으로 바꿉니다
- **저작권:** 음악·효과음·생성 이미지는 상업 이용 가능한 라이선스만 쓰고, 출처를 엔딩 화면과 게시글에 적습니다. 다른 회사 캐릭터·브랜드를 흉내 내지 않습니다
- **음량:** 소리는 `ffmpeg -af ebur128`로 재서 -16~-18 LUFS에 맞춥니다. Claude는 들을 수 없으니, 사람이 직접 들어 보고 확인합니다
- **표시:** 엔딩에 "앱 화면은 Pleos Connect 에뮬레이터 시연"과 음악 출처를 작게 넣습니다

## 만드는 순서

```bash
cd tools/demo/burung-toon
python3 build.py
npx hyperframes@0.8.196 check
npx hyperframes@0.8.196 snapshot --at 1,4,8,12,16,20,24,28,32,36,40   # 장면마다 프레임을 직접 보고 고침
npx hyperframes@0.8.196 render --quality delivery --video-frame-format png -o renders/burung-toon.mp4
```

1. 캐릭터 시트(아빠·아이·엄마·차) → 장면별 캐릭터 이미지 생성
2. `build.py`에 장면 목록(시간·캐릭터·앱 화면·자막·카메라 이동·효과음)을 정의
3. `check` → `snapshot`으로 프레임 확인(글자 위치, 캐릭터 일관성, 앱 화면이 읽히는지) → 고침 → `render`
4. 결과 파일 길이·해상도를 `ffprobe`로 확인
